# 画面確認の手順の出し方

ユーザーは初学者。画面確認をお願いするときは、**ユーザーが考えたり書き換えたりしなくてよい手順**にする。
PR #205（vue-router）で、「招待リンクをコピーして URL の `<コード>` 部分を置き換える」「1 項目に操作が 4 つ」という手順を出したら
「上手くいかない」と言われた。確認用データをこちらで作り、下の形に直したら全項目 OK になった（2026-09-27、ユーザーが「今後もこのパターンで」と依頼）。

## 1. 手順を出す前に、こちらでやること

- **サーバーの状態を確認する**（`lsof -i :3000` / `lsof -i :5173`）。止まっていれば起動手順を、再起動が要る変更（`config/application.rb`・モデルの enum・新しい npm パッケージなど）なら再起動の手順を先に書く（PID は確認した値を書く）
- **確認に使うデータを用意する**：招待コード・再設定トークン・確認用の本などは `bin/rails runner` で開発用 DB に作り、**そのまま貼れる完成した URL** にしておく
  ```bash
  cd backend && bin/rails runner 'owner = User.find_by!(email: "owner@example.com"); puts Invitation.create!(inviter: owner).code'
  cd backend && bin/rails runner 'puts User.find_by!(email: "test@mail.com").password_reset_token'
  ```
- **今の DB の状態は直前に読み直す**（隠した候補・本のジャンルなど。前に見た値を使い回さない → CLAUDE.md §9）。「今『リーダブルコード』は実用・暮らしです」のように具体的に書く
- **ユーザーは確認の合間に自由に操作する**（確認用タグをまとめる・外す、本物の本にタグを足す、など。2026-10-04）。手順を出す前と、後片付けの前に、確認用データも本物のデータも読み直す。**本物のデータ（確認用でない本など）が変わっていたら、勝手に戻さず、どうするか聞く**
- **管理者でない人の画面を確かめる**ときは、既存のアカウント（パスワードが分からない・変えたくない）を使わず、`bin/rails runner` で**確認用アカウント**を作る（例：`kakunin@example.com`、パスワードは `SecureRandom` で作ってコードブロックで渡す）。**シークレットウィンドウ**でログインしてもらい、確認後に本ごと消す（2026-10-04、PR #274）
- ファイルを選んでもらう確認（CSV 読み込みなど）は、確認用ファイルを**ユーザーが選びやすい `~/Downloads`** に置く（scratchpad は選びにくい）。ただし `~/Downloads` のファイルを消すコマンドは許可されないことがあるので、**最初から「確認後に消してください」と消すコマンドを添える**（2026-10-04）

## 2. 手順の形

~~~markdown
## 準備
（シークレットウィンドウを開く など。Chrome なら ⌘ + Shift + N）

## ① 〇〇（何を確かめるか、短く）

（どこで）開きます。

```
http://localhost:5173/register?invite=1s7BacCvP4ZX
```

→ **登録画面**が出て、招待コード欄に `1s7BacCvP4ZX` が入っていれば OK（登録はしなくて大丈夫です）
~~~

- **1 項目 = 1 つの操作 + 期待する結果**。操作が続くときは項目を分ける
- 同じ人が「できること」と「できないこと」の両方を確かめる手順（管理者でない人の「名前の変更はできる・書き方だけの変更はできない」など）は、**手順の前に、できる・できないを表にして見せる**。断られる項目のすぐあとに、できる項目があると「そもそもできないのでは？」と迷わせる（2026-10-04）
- URL・コマンド・入力する値は**コードブロック**に入れる（表のセルや文中に書かない。コピーボタンが付くように）
- **URL の一部を書き換えさせない**（`<コード>` のような置き換えは禁止。完成した URL を渡す）
- 期待する結果は、**画面に出る文字・アドレスバーの URL・色**など目で見て分かるもので書く（「正しく動く」は不可）
- **色は値や色の名前（「濃い紺」）だけで書かず、画面にある物と比べて書く**（「件数の『2』と同じ緑」「ほぼ黒」）。`#172b4d` を「濃い紺」と書いたら、ユーザーには黒に見えて「その色ではない」と言われた（2026-10-03、PR #260）
- 冊数・件数を変えたときは、境目だけでなく**一度に読み込む件数**（「もっと見る」の前に出る数）との関係も期待する結果に書き、多い件数（100 冊など）でも確かめる。左の段だけ 25 冊にしたら、60 冊読み込むと左 30・右 30 になり「25 冊になっていない」と言われた（2026-10-03、PR #252）
- 表のように**縦にそろえる画面**（列の見出し＋行）を作ったら、確認の項目に「**見出しの真下に値が来ているか**」を入れる（例：「『著者』の真下に著者名、『評価』の真下に ★」）。列のずれは自動テストでは見つからない（PR #211 の読了一覧で、見出しが値より右にずれたのを画面の確認で見つけた）
- **やってはいけない操作**があれば太字で書く（例：「パスワードは入力せず閉じてください（設定すると test@mail.com のパスワードが変わります）」）
- ログイン状態で結果が変わる確認は、**いつもの窓（ログイン済み）とシークレットウィンドウ（未ログイン）を分けて**、どちらでやるかを項目ごとに書く
- 項目は 5〜6 個までにする。多いときは 2 回に分ける

## 3. 返し方と、うまくいかなかったとき

- 最後に「**①OK ②OK …**のように返してください」と書く
- 「うまくいかない番号があれば、**その番号と画面に何が出たか**（例：②で真っ白、①でログイン画面が出た）を教えてください」と添える
- **ユーザーの Mac での動き**（2026-10-04 に確認）。手順はこれに合わせて書く
  - ダウンロードは**保存先を聞かれる**設定（小さな画面で「保存」を押す）。ファイル名の欄に空白が入ることがある
  - CSV をダブルクリックすると **Cursor（エディタ）**で開く。表で見てほしいときは「右クリック →『このアプリケーションで開く』→ Numbers」と書く
  - スクリーンショットは**デスクトップ**に「スクリーンショット 0008-10-04 16.36.47.png」（令和 8 年表記）で保存され、**ファイル名だけ**が届くことがある。そのときは `~/Desktop/` のその名前のファイルを Read で開いて見る
- 「上手くいかない」と言われたら、まずサーバー・URL・DB をこちらで確認し、原因が手順の分かりにくさなら**この形で出し直す**
- 「〜になっていない」が**こちらの想定どおりの動き**だったときは、想定（なぜそうなるか）を短く説明してから、**期待していた並び・数を選択肢で聞く**（2026-10-03、PR #252 で「左右 25 冊ずつ・計 50 冊」に決まった）。「訂正」とだけ届いたら、変更を始めず何を訂正するかを聞く

## 4. 後片付け

- 確認用に作ったデータ（招待コードなど）は、確認後にこちらで消すと書いておき、実際に消す
  ```bash
  cd backend && bin/rails runner 'Invitation.find_by(code: "1s7BacCvP4ZX")&.destroy'
  ```
- 見本ページ（色・配置の候補）は scratchpad に HTML を作って `open` で開く。アプリのコードは変えない
- 見た目の案は、見た目だけでなく**「1 画面に見える量」などの数字も添えて比べる**（本物と同じ余白・文字の大きさにそろえ、**計算ではなくブラウザで実測する**：見本に測る script を足した写しをヘッドレス Chrome で `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --window-size=1280,900 --virtual-time-budget=2000 --dump-dom file://…` で開き、結果を body の属性に書いて読む。2026-10-03、見込みで「A は約 14 冊」と書いたが実測は 8 冊だった）。例：表紙 44px / 60px は「カードが縦に伸びる」と思い込んで 44px をすすめたが、計算すると多くのカードは高さが同じで、60px に結論が変わった（2026-09-30）

## 関連

- 説明の書き方全般：用語に意味を添える・日本語で書く・コマンドはコードブロック（ユーザーのメモリにも記録あり）
- 状態を伝える前に確認：CLAUDE.md §9
- サーバーのポート：`enforce-default-ports` スキル
