# 読書管理アプリ — 画面設計

> この文書は [要件定義書（概要）](requirements.md) から分割した詳細ドキュメントです。
> 画面・部品（S1〜S4）とその表示項目・操作・レスポンシブ挙動をまとめます。
> 画面遷移図・データフローの図解は [基本設計（図）](basic-design.md) を参照してください。

関連：[機能要件](functional-requirements.md) / [データベース設計](database-design.md) / [技術スタック](tech-stack.md)

対象デバイス: PC 優先。スマホ/タブレットではレスポンシブに再配置する（非機能要件は [要件定義書](requirements.md) 参照）。

画面の見た目・操作感は [`prototype/`](../prototype/)（HTML/CSS/JS のモック）を参照実装とする。

## 1. 画面一覧

| ID | 画面/要素 | 目的 |
|---|---|---|
| S1 | カンバンボード（メイン） | 蔵書を 3 カラムで一覧・状態管理 |
| S2 | 書籍カード（部品） | 1 冊の要約表示と移動・編集の起点 |
| S3 | 追加フォーム | 新規書籍の登録 |
| S4 | 編集フォーム | 既存書籍の編集・削除 |
| S5 | ログイン / 新規登録 / パスワード再設定 | ログイン。招待コードでのアカウント登録。再設定リンクからの新パスワード設定 |
| S6 | 管理（管理者のみ） | 招待コードの発行・一覧・削除、ユーザー一覧と再設定リンクの発行 |
| S7 | アカウント | パスワード変更・アカウント削除 |

## 2. S1 カンバンボード

- **表示項目**：3 カラム（読みたい / 読書中 / 読了）。各カラム見出しにカラム名＋件数（総件数）。各カラム内に書籍カードを縦に並べる。
- **ページング**：各カラムは初期 20 件。続きがあればカラム末尾に「もっと見る（残り N 件）」ボタンを出し、押すと 20 件ずつ追加する。
- **ヘッダの絞り込み**：著者名検索（部分一致）／ジャンル選択／タグ選択（選択肢は使用中タグから生成）。3 つは併用でき、件数も連動する（[機能要件](functional-requirements.md) F11）。
- **読了カラムの並び替え**：読了カラム見出しに並び替え UI（読了日 / 評価 / 登録日 / 所要日数）＋昇順・降順トグル。既定は読了日・降順（F10）。同じ値の本はタイトル順。読了カラムはキーで並ぶため、カラム内のドラッグ並び替えはできない（他カラムからのドロップで状態変更のみ）。
- **操作**：「追加」ボタンで S3 を開く。カードをドラッグして別カラムへ移動（＝状態変更）。カードクリックで S4 を開く。
- **レスポンシブ**：PC は 3 カラム横並び。スマホは**縦積み**（1 カラムずつ縦に並べる）。

```
┌── 読書管理ボード ──[著者検索][ジャンル▼][タグ▼]──── [＋追加] ┐
│  読みたい (3)      読書中 (2)      読了 (3) [並び替え▼][↓]   │
│ ┌──────────┐   ┌──────────┐   ┌──────────┐          │
│ │ 書籍カード │   │ 書籍カード │   │ 書籍カード │          │
│ │ (S2)     │   │          │   │ ★★★★☆  │          │
│ └──────────┘   └──────────┘   └──────────┘          │
│ ┌──────────┐                  ┌──────────┐          │
│ │ 書籍カード │                  │ 書籍カード │          │
│ └──────────┘                  └──────────┘          │
└────────────────────────────────────────────────────┘
```

## 3. S2 書籍カード

- **表示項目**：
  - 主ジャンルのバッジ（色分け）、雑誌なら「雑誌」バッジ
  - タイトル、著者、★評価（未評価は非表示 or グレー）
  - タグ（chip、複数）
  - 日付：現在のカラムに入った日を「登録/開始/読了 + 日付」で表示（履歴があれば複数）
  - 読了カードのみ「開始→読了 N日」（所要日数。算出不可なら非表示）
- **バッジ配色**：ジャンル・形態バッジは明るいパステル地＋同系の濃文字でトーンを統一（プロトタイプ準拠。文字コントラストは WCAG AA 目安）。
- **操作**：クリックで S4（編集）を開く。ドラッグで別カラムへ移動（＝状態変更、日付を記録）。

---

## 4. S3 追加フォーム

- **コードから登録**（フォーム先頭）：ISBN/JAN 入力＋「検索」、対応環境では「📷 バーコード読取」。取得成功でタイトル・著者・書影を自動補完し、形態（書籍/雑誌）を自動セット。雑誌・該当なし・失敗時は手入力にフォールバック（[機能要件](functional-requirements.md) F6）。
- **入力項目**：タイトル（必須）、著者（任意）、初期ステータス（既定「読みたい」）、**ジャンル**（select）、**形態**（書籍/雑誌）、**タグ**（カンマ区切り）。
- **タグ提案**：タグ欄の下に、タイトル・著者名から導いた候補タグをクリック可能な chip で表示。クリックで追加（F8）。
- **操作**：保存（登録して閉じる）／キャンセル（破棄して閉じる）。
- **表示形式**：モーダル想定。

---

## 5. S4 編集フォーム

- **入力項目**：タイトル、著者、ステータス、**ジャンル**、**形態**、**タグ**、★評価、感想メモ。
- **タグ提案**：S3 と同様（タイトル・著者から候補、既存タグは除外）。
- **操作**：更新／削除（確認の上）／キャンセル。
- **表示形式**：モーダル想定。

---

## 5.1 S5 ログイン / 新規登録 / パスワード再設定

- **ログイン**：メールアドレス・パスワード。下部の「招待コードをお持ちの方はこちら（新規登録）」で登録画面へ切り替え。「パスワードを忘れた場合は、管理者に再設定リンクを依頼してください」の案内を表示。
- **新規登録**：招待コード・メールアドレス・パスワード（8 文字以上）・確認。送信前に長さ・一致をヒント表示。成功するとログイン状態でボードを開く（本は空）。
- **招待リンク**：`/?invite=<コード>` で開くと登録画面をコード入力済みで表示。登録後は URL からコードを消す。
- エラー（招待コードが無効・メール登録済み・形式不正など）はフォーム上部に表示。
- **パスワード再設定**：管理者が発行した `/?reset=<トークン>` で開くと、ログイン状態に関係なく再設定画面を表示。開いた時点でリンクを確認し、使えれば「<メール> の新しいパスワードを設定してください」とフォームを出す。無効・期限切れ・使用済みならフォームを出さずにメッセージと「ログイン画面へ」を表示。新しいパスワード（8 文字以上）・確認を入力し、成功するとそのユーザーでログインしてボードを開く（他の端末はログアウト）。URL からトークンを消す。無効・期限切れ・使用済みのリンクは「再設定リンクが無効か、期限切れです」。

## 5.2 S6 管理（管理者のみ）

- ヘッダーの「管理」ボタン（管理者だけに表示）からモーダルで開く。「招待」「ユーザー」のタブで切り替え。

**招待タブ**
- 「招待コードを発行」で新しいコードを一覧の先頭に追加。コードは 1 回限り・発行から 7 日で期限切れ。
- 一覧：コード・状態（未使用 / 使用済み / 期限切れ）・期限、使用済みは登録したユーザーのメール。
- 未使用のコードは「リンクをコピー」（招待リンクをクリップボードへ）と「削除」ができる。

**ユーザータブ**

- ユーザー一覧（メール・管理者バッジ・登録日）。各ユーザーに「再設定リンクを発行」ボタン。
- 自分の行には「（自分）」を表示。自分宛ての発行はすぐには行わず、「あなた自身のパスワードを再設定するリンクです。今のパスワードが分かる場合は『アカウント』→『パスワード変更』を使ってください」と確認（「発行する」/「やめる」）を出す。禁止しないのは、ログインしたままパスワードを忘れた管理者の復旧手段として残すため。
- 発行したリンクはそのユーザーの下に表示し、「リンクをコピー」と期限（24 時間）を出す。リンクは保存されないため、モーダルを閉じると再表示できない（必要なら再発行）。

## 5.3 S7 アカウント

- ヘッダーの「アカウント」ボタンからモーダルで開く。「パスワード変更」「アカウント削除」のタブで切り替え。
- **パスワード変更**：現在のパスワード・新しいパスワード（8 文字以上）・確認。成功すると他の端末はログアウトされる。
- **アカウント削除**：現在のパスワード＋「すべてのデータが削除されることを理解しました」にチェックすると削除ボタンが押せる。削除後はログイン画面へ。最後の管理者は削除できない。

## 6. ステータス遷移

```
[読みたい] ⇄ [読書中] ⇄ [読了]
```

カード移動 = 該当書籍の `status` を PATCH で更新する（`status` 値の定義は [データベース設計](database-design.md)、API は [機能要件](functional-requirements.md) を参照）。遷移方向の制約は設けない（任意のカラムへ移動可）。
