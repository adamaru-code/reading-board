## 1. 機能要件

| ID | 要件 |
|---|---|
| F1 | 書籍を登録・一覧表示・編集・削除できる（CRUD） |
| F2 | カンバンのカラム移動で書籍のステータスを変更できる（読みたい → 読書中 → 読了、逆方向も可） |
| F3 | 書籍に評価（★1〜5）を記録できる |
| F4 | 書籍に感想メモを記録できる |
| F5 | ステータスで絞り込んで一覧を取得できる（例: 読書中のみ） |
| F6 | ISBN/バーコード（13桁 JAN・ISBN-10 も可）から書誌情報（タイトル・著者・書影）を取得して登録できる。書籍/雑誌を判定し形態に反映（openBD 利用。雑誌は自動取得非対応で手入力にフォールバック） |
| F7 | 書籍に**種別**を設定できる：主ジャンル（単一）・形態（書籍/雑誌）・タグ（複数・自由） |
| F8 | タイトル・著者名から**候補タグを提案**し、クリックで追加できる（重複除去・語彙統一） |
| F9 | 各ステータスに**入った日付を記録**（登録日・開始日・読了日、履歴として複数可）し、読了までの**所要日数**を表示できる |
| F10 | **読了カラムを並び替え**できる（読了日 / 評価 / 登録日 / 所要日数、昇順・降順） |
| F11 | **ジャンル・著者名（部分一致）・タグ**で一覧を絞り込める（互いに併用可） |

各機能の画面挙動は [`prototype/`](../prototype/) を参照実装とする。

## 2. ユースフロー / 操作フロー

### 2.1 アクター

- **利用者**：読書する本人（単一ユーザー）。本アプリの唯一の操作者。

### 2.2 主要ユースケース

| ID | ユースケース | 概要 |
|---|---|---|
| UC1 | 本を登録する | 読みたい本をリストに追加する（手入力 or ISBN/バーコード） |
| UC2 | 読み始める | 「読みたい」の本を「読書中」に移す |
| UC3 | 読了して評価する | 「読了」に移し、★評価・感想を記録する |
| UC4 | 本を編集・削除する | 情報を修正、または不要な本を削除する |
| UC5 | 状態で絞り込む | 読書中だけ、など状態別に一覧する |
| UC6 | コードから登録する | ISBN 入力 or バーコード読取 → 書誌を自動補完 → 保存 |
| UC7 | 種別で整理する | 主ジャンル・形態・タグを付け、ジャンル/著者/タグで絞り込む |
| UC8 | 読書 log を見る | 登録日・開始日・読了日、所要日数を確認し、読了を並び替える |

### 2.3 代表フロー

UC1 本を登録する:

```
[ボードで「追加」] → [フォームにタイトル(必須)・著者・初期ステータス入力]
   → [保存] → [該当カラムにカードが表示される]
```

UC2/UC3 状態を変える（カンバンの中心操作）:

```
[カードを別カラムへドラッグ] → [status を PATCH 更新] → [移動先カラムに再配置]
   （読了に移したら、カード編集で ★評価・感想メモを記録）
```

UC4 編集・削除:

```
[カードをクリック] → [編集フォーム] → [更新] または [削除]
```

UC6 コードから登録:

```
[追加フォームで ISBN 入力 or 「バーコード読取」] → [openBD 照会]
   → 書籍(978/979): タイトル・著者・書影を自動補完 / 形態=書籍
   → 雑誌(491)・該当なし・通信失敗: 手入力にフォールバック
   → [必要なら種別・タグを付与] → [保存]
```

UC8 読書 log（日付・所要日数・並び替え）:

```
[登録=読みたいに入った日 / 読書中に移した日=開始 / 読了に移した日=読了] を自動記録
   → 読了カードに「開始→読了 N日」を表示
   → 読了カラムを 読了日/評価/登録日/所要日数 で昇降切替
```

各操作に対応する画面（S1〜S4）は [画面設計](screen-design.md) を参照。

## 3. API 仕様（REST / JSON）

ベースパス `/api`。フロントの Vite プロキシで `/api → http://localhost:3000` に転送される。
リクエスト/レスポンスのフィールドと `status` enum は [データベース設計](database-design.md) に準拠する。

| メソッド | パス | 用途 | 主なステータス |
|---|---|---|---|
| GET | `/api/books` | 一覧取得。絞り込み併用可: `?status=reading` / `?genre=liberal_arts` / `?author=夏目`（部分一致） / `?tag=名著` | 200 |
| GET | `/api/books/:id` | 詳細取得 | 200 / 404 |
| POST | `/api/books` | 新規作成（種別・タグ含む） | 201 / 422 |
| PATCH | `/api/books/:id` | 更新（ステータス変更・評価・メモ・種別・タグ含む） | 200 / 404 / 422 |
| DELETE | `/api/books/:id` | 削除 | 204 / 404 |
| GET | `/api/books/lookup?isbn=<code>` | ISBN/JAN から書誌取得（本番はバックエンドが openBD をプロキシ。プロトタイプはフロントから openBD を直接照会） | 200 / 404 |

- `status` / `genre` / `media_type` の enum 値、`tags` の形式は [データベース設計](database-design.md) に準拠。
- 一覧の絞り込みは AND（指定した条件をすべて満たす本を返す）。
- 状態変更（PATCH で `status` 更新）時にサーバー側で**状態イベント**（入った日）を記録する（[データベース設計](database-design.md) §6）。所要日数はイベントから算出（保存しない）。
- **タグ提案**：本フェーズは辞書ベース（タイトル・著者から候補を生成）。実装場所はクライアント or `GET /api/books/tag_suggestions?title=&author=`。将来は AI/API 化（[要件定義書](requirements.md) §4.2）。

### 3.1 リクエスト/レスポンス例

作成リクエスト（POST /api/books）:

```json
{
  "book": {
    "title": "こころ",
    "author": "夏目 漱石",
    "status": "want_to_read",
    "isbn": "9784101010137",
    "genre": "classic_novel",
    "media_type": "book",
    "tags": ["名著", "再読したい"]
  }
}
```

レスポンス（201）:

```json
{
  "id": 1,
  "title": "こころ",
  "author": "夏目 漱石",
  "status": "want_to_read",
  "isbn": "9784101010137",
  "genre": "classic_novel",
  "media_type": "book",
  "rating": null,
  "memo": null,
  "tags": ["名著", "再読したい"],
  "position": 1,
  "status_dates": {
    "want_to_read": ["2026-07-10"],
    "reading": [],
    "read": []
  },
  "reading_duration_days": null,
  "created_at": "2026-07-10T12:00:00Z",
  "updated_at": "2026-07-10T12:00:00Z"
}
```

- `tags` は文字列配列でやり取り（内部は多対多）。`status_dates` は各状態に入った日（履歴）。`reading_duration_days` は開始→読了の所要日数（読了時のみ・イベントから算出）。

エラー（422）:

```json
{ "errors": { "title": ["can't be blank"] } }
```
