## 1. 機能要件

| ID | 要件 |
|---|---|
| F1 | 書籍を登録・一覧表示・編集・削除できる（CRUD） |
| F2 | カンバンのカラム移動で書籍のステータスを変更できる（読みたい → 読書中 → 読了、逆方向も可） |
| F3 | 書籍に評価（★1〜5）を記録できる |
| F4 | 書籍に感想メモを記録できる |
| F5 | ステータスで絞り込んで一覧を取得できる（例: 読書中のみ） |
| F6 | ISBN/バーコード（13桁 JAN・ISBN-10 も可）から書誌情報（タイトル・著者）を取得して登録できる。書籍/雑誌を判定し形態に反映（openBD をバックエンド経由で照会。雑誌・該当なし・失敗時は手入力にフォールバック） |
| F7 | 書籍に**種別**を設定できる：主ジャンル（単一）・形態（書籍/雑誌）・タグ（複数・自由） |
| F8 | タイトル・著者名と**過去に付けたタグ**から**候補タグを提案**し、クリックで追加できる。入力中の文字で候補を絞り込める（重複除去・語彙統一） |
| F9 | 各ステータスに**入った日付を記録**（登録日・開始日・読了日、履歴として複数可）し、読了までの**所要日数**を表示できる |
| F10 | **読了カラムを並び替え**できる（読了日 / 評価 / 登録日 / 所要日数、昇順・降順） |
| F11 | **ジャンル・著者名（部分一致）・タグ**で一覧を絞り込める（互いに併用可） |
| F12 | カラム内で**ドラッグして並び替え**でき、並び順を保存する（読了カラムはキーで並ぶため対象外） |
| F13 | 一覧は**カラムごとにページング**し、初期 20 件＋「もっと見る」で追加表示する |
| F14 | **ログイン / ログアウト**できる（メール＋パスワード、セッション Cookie）。本は所有者だけが見られる |
| F15 | **招待制で新規登録**できる。管理者が招待コード（1 回限り・7 日）を発行し、コードを持つ人が登録する |
| F16 | **パスワード変更・アカウント削除**ができる。パスワードを忘れた場合は**管理者が再設定リンク**（24 時間・1 回限り）を発行する |
| F17 | ログイン・登録・パスワード変更などは IP ごとに**回数制限**する（超過は 429） |

各機能の画面挙動は [`prototype/`](../prototype/) を参照実装とする。

## 2. ユースフロー / 操作フロー

### 2.1 アクター

- **利用者**：読書する本人。自分の本だけを見て管理する（他の利用者の本は見えない）。
- **管理者**：利用者のうち `admin` の人（初期ユーザー）。招待コードの発行と、パスワード再設定リンクの発行ができる。

### 2.2 主要ユースケース

| ID | ユースケース | 概要 |
|---|---|---|
| UC1 | 本を登録する | 読みたい本をリストに追加する（手入力 or ISBN/バーコード） |
| UC2 | 読み始める | 「読みたい」の本を「読書中」に移す |
| UC3 | 読了して評価する | 「読了」に移し、★評価・感想を記録する |
| UC4 | 本を編集・削除する | 情報を修正、または不要な本を削除する |
| UC5 | 状態で絞り込む | 読書中だけ、など状態別に一覧する |
| UC6 | コードから登録する | ISBN 入力 or バーコード読取 → 書誌を自動補完 → 保存 |
| UC7 | 種別で整理する | 主ジャンル・形態・タグを付け、ジャンル/著者/タグで絞り込む |
| UC8 | 読書 log を見る | 登録日・開始日・読了日、所要日数を確認し、読了を並び替える |
| UC9 | 招待して登録してもらう | 管理者が招待コードを発行してリンクを渡し、相手がリンクから登録する |
| UC10 | アカウントを管理する | パスワード変更・アカウント削除。忘れた場合は管理者に再設定リンクを依頼する |

### 2.3 代表フロー

UC1 本を登録する:

```
[ボードで「追加」] → [フォームにタイトル(必須)・著者・初期ステータス入力]
   → [保存] → [該当カラムにカードが表示される]
```

UC2/UC3 状態を変える（カンバンの中心操作）:

```
[カードを別カラムへドラッグ] → [status を PATCH 更新] → [移動先カラムに再配置]
   （読了に移したら、カード編集で ★評価・感想メモを記録）
```

UC4 編集・削除:

```
[カードをクリック] → [編集フォーム] → [更新] または [削除]
```

UC6 コードから登録:

```
[追加フォームで ISBN 入力 or 「バーコード読取」] → [openBD 照会]
   → 書籍(978/979): タイトル・著者を自動補完 / 形態=書籍
   → 雑誌(491)・該当なし・通信失敗: 手入力にフォールバック
   → [必要なら種別・タグを付与] → [保存]
```

UC8 読書 log（日付・所要日数・並び替え）:

```
[登録=読みたいに入った日 / 読書中に移した日=開始 / 読了に移した日=読了] を自動記録
   → 読了カードに「開始→読了 N日」を表示
   → 読了カラムを 読了日/評価/登録日/所要日数 で昇降切替
```

UC9 招待して登録してもらう:

```
[管理者: ヘッダ「管理」→ 招待タブで発行 → リンクをコピーして渡す]
   → [相手: /?invite=<コード> を開く → 登録画面（コード入力済み）でメール・パスワード → 登録]
   → [ログイン状態でボード（本は空）]
```

各操作に対応する画面（S1〜S7）は [画面設計](screen-design.md) を参照。

## 3. API 仕様（REST / JSON）

ベースパス `/api`。開発ではフロントの Vite プロキシが `/api → http://localhost:3000` に転送する（本番は nginx が同じ役割）。
`/api/books*`・パスワード変更・アカウント削除などは**ログイン必須**（未ログインは 401）で、本は常にログイン中のユーザーのものだけを扱う（他人の本は 404）。
リクエスト/レスポンスのフィールドと enum 値は [データベース設計](database-design.md) に準拠する。画面との対応は [基本設計](basic-design.md) §4.3。

### 3.1 書籍

| メソッド | パス | 用途 | 主なステータス |
|---|---|---|---|
| GET | `/api/books` | 一覧（1 ページ分）。絞り込み `status` / `genre` / `author`（部分一致）/ `tag`（AND）、並び `sort`（`finished_on` / `registered_on` / `rating` / `duration_days`）＋`dir`（`asc`/`desc`）、範囲 `page` または `offset` ＋ `per_page`（既定 100・1〜200） | 200 |
| GET | `/api/books/:id` | 詳細 | 200 / 404 |
| POST | `/api/books` | 新規作成（種別・タグ含む） | 201 / 400 / 422 |
| PATCH | `/api/books/:id` | 更新（状態・評価・メモ・種別・タグなど） | 200 / 400 / 404 / 422 |
| DELETE | `/api/books/:id` | 削除 | 204 / 404 |
| PATCH | `/api/books/reorder` | カラム内の並び順を保存（`{ ids: [...] }` の順に position を振り、同じ状態の残りは既存順で後ろに詰める） | 204 |
| GET | `/api/books/lookup?isbn=<code>` | ISBN/JAN から書誌を取得（バックエンドが openBD を照会） | 200 / 422（不正な ISBN） |

- 不正な enum 値（例：`status: "flying"`）は検証エラーの 422。`book` キーが無いなどリクエストの形が違う場合は 400。
- 状態変更（作成・`status` 更新）時にサーバー側で**状態イベント**（入った日）を記録する（[データベース設計](database-design.md) §6）。登録日・開始日・読了日・所要日数はイベントから算出して返す（保存しない）。
- **タグ提案**はクライアント側で行う（`frontend/src/lib/tagSuggestions.ts`。API は無い）。辞書の候補に加え、自分の本に付いているタグ（一覧 API から集計）を候補にし、入力中の文字で絞り込む。
- `lookup` は該当なしでも 200 で `found: false` を返す（手入力にフォールバック）。

### 3.2 認証・アカウント

| メソッド | パス | 用途 | 主なステータス |
|---|---|---|---|
| GET | `/api/session` | ログイン中のユーザー（`id` / `email` / `admin`） | 200 / 401 |
| POST | `/api/session` | ログイン（`email` / `password`） | 200 / 401 / 429 |
| DELETE | `/api/session` | ログアウト | 204 |
| PATCH | `/api/password` | パスワード変更（`current_password` / `password` / `password_confirmation`）。他端末のセッションは失効 | 204 / 422 / 429 |
| POST | `/api/registration` | 招待コードで登録（`invitation_code` / `email` / `password` / `password_confirmation`）→ ログイン状態に | 201 / 422 / 429 |
| DELETE | `/api/registration` | アカウント削除（`current_password`）。最後の管理者は不可 | 204 / 422 / 429 |
| GET | `/api/password_reset?token=` | 再設定リンクが使えるか確認（使えれば `{ email }`） | 200 / 422 |
| PATCH | `/api/password_reset` | 再設定リンクから新しいパスワードを設定（`token` / `password` / `password_confirmation`）→ ログイン状態に | 200 / 422 / 429 |

### 3.3 管理（管理者のみ。一般ユーザーは 403）

| メソッド | パス | 用途 | 主なステータス |
|---|---|---|---|
| GET | `/api/invitations` | 自分が発行した招待の一覧（状態・期限・使った人） | 200 |
| POST | `/api/invitations` | 招待コードを発行（1 回限り・7 日） | 201 |
| DELETE | `/api/invitations/:id` | 未使用の招待を削除 | 204 / 404 / 422（使用済み） |
| GET | `/api/users` | ユーザー一覧 | 200 |
| POST | `/api/users/:user_id/password_reset_link` | パスワード再設定トークンを発行（24 時間・1 回限り。保存しない） | 201 / 404 |

### 3.4 リクエスト/レスポンス例

作成リクエスト（POST /api/books）:

```json
{
  "book": {
    "title": "こころ",
    "author": "夏目 漱石",
    "status": "want_to_read",
    "genre": "classic_novel",
    "media_type": "book",
    "tags": ["名著", "再読したい"]
  }
}
```

レスポンス（201）。書籍 1 件の形は一覧・詳細・更新でも同じ:

```json
{
  "id": 1,
  "title": "こころ",
  "author": "夏目 漱石",
  "status": "want_to_read",
  "genre": "classic_novel",
  "media_type": "book",
  "rating": null,
  "memo": null,
  "position": null,
  "tags": ["名著", "再読したい"],
  "registered_on": "2026-07-10",
  "started_on": null,
  "finished_on": null,
  "duration_days": null,
  "created_at": "2026-07-10T03:00:00.000Z",
  "updated_at": "2026-07-10T03:00:00.000Z"
}
```

- `tags` は文字列配列でやり取り（内部は多対多）。`registered_on` / `started_on` / `finished_on` は各状態に**最初に入った日**、`duration_days` は開始→読了の日数（両方あるときのみ）。
- ISBN は照会（`lookup`）にだけ使い、書籍には保存しない。

一覧レスポンス（GET /api/books）:

```json
{
  "items": [ { "id": 1, "title": "こころ", "...": "（上と同じ形）" } ],
  "pagination": { "page": 1, "per_page": 20, "total": 47, "total_pages": 3 }
}
```

エラー（422 など）。`errors` はメッセージの配列:

```json
{ "errors": ["Title can't be blank"] }
```

- 認証・招待・パスワード関連のメッセージは日本語（例：`"招待コードが無効です"`）。モデルの検証メッセージは現状英語（I18n 化は #160）。
