# 読書管理アプリ — 要件定義・設計

Trello 風カンバンで書籍を「読みたい / 読書中 / 読了」の 3 カラム管理するアプリの
要件定義・設計をまとめる。技術スタックは [CLAUDE.md](../CLAUDE.md) 参照（Rails 8 API / Vue 3 / MySQL 8）。

> 本アプリは個人利用だが、本書は**お客さん向け要件定義書を意識した版**として、背景・スコープ・
> 非機能要件・ユースフロー・画面仕様・技術選定まで明文化する。フィールド名や enum 値など「決め事」は
> §4（非機能要件）・§7（データモデル）・§8（API 仕様）の表に明示しており、レビューで調整可能。

---

## 1. 背景・目的・課題

### 1.1 背景

読みたい本・読んでいる本・読み終えた本が頭の中や複数のメモに散らばり、**積読の把握や読書の進捗が見えにくい**。
紙のリストや汎用メモアプリでは「状態の移り変わり」を直感的に扱えない。

### 1.2 目的

書籍を **「読みたい → 読書中 → 読了」** の 3 状態でカンバン管理し、**読書状況を一目で可視化**する。
評価・感想メモも残せるようにし、読後の振り返りに使えるようにする。

### 1.3 解決する課題

| 課題 | 本アプリでの解決 |
|---|---|
| 積読・読書中の本が把握しづらい | カンバンの 3 カラムで状態を可視化 |
| 状態変更が手間 | カード移動（ドラッグ）で状態を更新 |
| 読後の評価・感想が残らない | ★評価・感想メモを書籍ごとに記録 |

---

## 2. スコープ

### 2.1 対象（このフェーズで作る）

- 書籍の登録・一覧・編集・削除（CRUD）
- カンバンのカラム移動によるステータス変更
- ★1〜5 の評価、感想メモの記録
- ステータスによる絞り込み表示

### 2.2 対象外（今回は作らない）

- ユーザー認証・アカウント管理（→ §4.7 で将来想定を明記）
- 複数ユーザーでの共有・コラボレーション
- 全文検索、タグ・カテゴリ、読書 log/統計グラフ
- 外部サービス連携（書影 API・書誌情報の自動取得など）
- 多言語対応（日本語 UI 前提）

---

## 3. 機能要件

| ID | 要件 |
|---|---|
| F1 | 書籍を登録・一覧表示・編集・削除できる（CRUD） |
| F2 | カンバンのカラム移動で書籍のステータスを変更できる（読みたい → 読書中 → 読了、逆方向も可） |
| F3 | 書籍に評価（★1〜5）を記録できる |
| F4 | 書籍に感想メモを記録できる |
| F5 | ステータスで絞り込んで一覧を取得できる（例: 読書中のみ） |

## 4. 非機能要件

| 区分 | 要件 |
|---|---|
| 4.1 性能 | 蔵書 〜1,000 冊での一覧表示が**体感 2 秒以内**。API 応答は通常 **500ms 以内**。1,000 冊超を見据え、将来ページング（1 回 50〜100 件）を導入できる設計余地を残す |
| 4.2 想定利用者・同時実行 | **単一ユーザー**を前提。同時アクセスは基本 1、ピークでも数セッション程度 |
| 4.3 データ規模 | 蔵書 **〜1,000 冊**を想定 |
| 4.4 対応ブラウザ | モダンブラウザ最新版（Chrome / Edge / Safari / Firefox）。IE は非対応 |
| 4.5 対応デバイス | **PC 優先＋スマホ・タブレット対応（レスポンシブ）**。スマホでは 3 カラムを縦積みに切り替え |
| 4.6 可用性 | 個人利用のため SLA は設けず**ベストエフォート**。ローカル / 自己ホスト前提 |
| 4.7 セキュリティ | 認証は本フェーズ対象外だが、**将来的に単一ユーザー認証（メール＋パスワード等）を追加する前提**でモデル/API を拡張しやすく保つ。CORS は許可オリジンを `http://localhost:5173` に限定（[CLAUDE.md](../CLAUDE.md) §8）。本番は HTTPS 前提。入力値は**サーバー側でも検証**する |
| 4.8 保守性・品質 | モデル/API をテスト（minitest）で担保。開発は Issue → Branch → PR フロー（[CLAUDE.md](../CLAUDE.md) §1）。フロントは TypeScript の型と Lint で品質を確保 |
| 4.9 国際化・A11y | 日本語 UI 前提（多言語は対象外）。アクセシビリティは最低限（キーボード操作・十分なコントラスト）を意識し、厳密な WCAG 準拠は対象外 |
| 4.10 ポート | ローカルは Backend 3000 / Frontend 5173 / MySQL 3306 を厳守（[CLAUDE.md](../CLAUDE.md) §8） |

## 5. ユースフロー / 操作フロー

### 5.1 アクター

- **利用者**：読書する本人（単一ユーザー）。本アプリの唯一の操作者。

### 5.2 主要ユースケース

| ID | ユースケース | 概要 |
|---|---|---|
| UC1 | 本を登録する | 読みたい本をリストに追加する |
| UC2 | 読み始める | 「読みたい」の本を「読書中」に移す |
| UC3 | 読了して評価する | 「読了」に移し、★評価・感想を記録する |
| UC4 | 本を編集・削除する | 情報を修正、または不要な本を削除する |
| UC5 | 状態で絞り込む | 読書中だけ、など状態別に一覧する |

### 5.3 代表フロー

UC1 本を登録する:

```
[ボードで「追加」] → [フォームにタイトル(必須)・著者・初期ステータス入力]
   → [保存] → [該当カラムにカードが表示される]
```

UC2/UC3 状態を変える（カンバンの中心操作）:

```
[カードを別カラムへドラッグ] → [status を PATCH 更新] → [移動先カラムに再配置]
   （読了に移したら、カード編集で ★評価・感想メモを記録）
```

UC4 編集・削除:

```
[カードをクリック] → [編集フォーム] → [更新] または [削除]
```

## 6. 画面仕様（詳細）

対象デバイス: PC 優先。スマホ/タブレットではレスポンシブに再配置する（§4.5）。

### 6.1 画面一覧

| ID | 画面/要素 | 目的 |
|---|---|---|
| S1 | カンバンボード（メイン） | 蔵書を 3 カラムで一覧・状態管理 |
| S2 | 書籍カード（部品） | 1 冊の要約表示と移動・編集の起点 |
| S3 | 追加フォーム | 新規書籍の登録 |
| S4 | 編集フォーム | 既存書籍の編集・削除 |

### 6.2 S1 カンバンボード

- **表示項目**：3 カラム（読みたい / 読書中 / 読了）。各カラム見出しにカラム名＋件数。各カラム内に書籍カードを縦に並べる。
- **操作**：「追加」ボタンで S3 を開く。カードをドラッグして別カラムへ移動（＝状態変更）。カードクリックで S4 を開く。
- **レスポンシブ**：PC は 3 カラム横並び。スマホは**縦積み**（1 カラムずつ縦に並べる）。

```
┌───────────────── 読書管理ボード ────────────  [＋追加] ┐
│  読みたい (3)      読書中 (2)        読了 (5)          │
│ ┌──────────┐   ┌──────────┐   ┌──────────┐        │
│ │ 書籍カード │   │ 書籍カード │   │ 書籍カード │        │
│ │ (S2)     │   │          │   │ ★★★★☆  │        │
│ └──────────┘   └──────────┘   └──────────┘        │
│ ┌──────────┐                  ┌──────────┐        │
│ │ 書籍カード │                  │ 書籍カード │        │
│ └──────────┘                  └──────────┘        │
└──────────────────────────────────────────────────┘
```

### 6.3 S2 書籍カード

- **表示項目**：タイトル、著者、★評価（未評価は非表示 or グレー）。
- **操作**：クリックで S4（編集）を開く。ドラッグで別カラムへ移動。

### 6.4 S3 追加フォーム

- **入力項目**：タイトル（必須）、著者（任意）、初期ステータス（既定「読みたい」）。
- **操作**：保存（登録して閉じる）／キャンセル（破棄して閉じる）。
- **表示形式**：モーダル想定。

### 6.5 S4 編集フォーム

- **入力項目**：タイトル、著者、ステータス、★評価、感想メモ。
- **操作**：更新／削除（確認の上）／キャンセル。
- **表示形式**：モーダル想定。

### 6.6 ステータス遷移

```
[読みたい] ⇄ [読書中] ⇄ [読了]
```

カード移動 = 該当書籍の `status` を PATCH で更新する。遷移方向の制約は設けない（任意のカラムへ移動可）。

## 7. データモデル

### Book

| フィールド | 型 | 制約 | 説明 |
|---|---|---|---|
| `id` | bigint | PK, auto | 主キー |
| `title` | string | NOT NULL | 書名（必須） |
| `author` | string | NULL 可 | 著者名 |
| `status` | integer(enum) | NOT NULL, default: `want_to_read` | 状態（下記 enum） |
| `rating` | integer | NULL 可, 0〜5 | 評価（★）。0/未設定は評価なし |
| `memo` | text | NULL 可 | 感想メモ |
| `position` | integer | NULL 可 | カラム内の並び順（将来の並べ替え用） |
| `created_at` | datetime | NOT NULL | 作成日時 |
| `updated_at` | datetime | NOT NULL | 更新日時 |

### status enum（Rails `enum`）

| 値（Vue/API） | 整数 | 表示（カラム名） |
|---|---|---|
| `want_to_read` | 0 | 読みたい |
| `reading` | 1 | 読書中 |
| `read` | 2 | 読了 |

## 8. API 仕様（REST / JSON）

ベースパス `/api`。フロントの Vite プロキシで `/api → http://localhost:3000` に転送される。

| メソッド | パス | 用途 | 主なステータス |
|---|---|---|---|
| GET | `/api/books` | 一覧取得（status で絞り込み可: `?status=reading`） | 200 |
| GET | `/api/books/:id` | 詳細取得 | 200 / 404 |
| POST | `/api/books` | 新規作成 | 201 / 422 |
| PATCH | `/api/books/:id` | 更新（ステータス変更・評価・メモ含む） | 200 / 404 / 422 |
| DELETE | `/api/books/:id` | 削除 | 204 / 404 |

### リクエスト/レスポンス例

作成リクエスト（POST /api/books）:

```json
{ "book": { "title": "リーダブルコード", "author": "Dustin Boswell", "status": "want_to_read" } }
```

レスポンス（201）:

```json
{
  "id": 1,
  "title": "リーダブルコード",
  "author": "Dustin Boswell",
  "status": "want_to_read",
  "rating": null,
  "memo": null,
  "position": 1,
  "created_at": "2026-07-06T12:00:00Z",
  "updated_at": "2026-07-06T12:00:00Z"
}
```

エラー（422）:

```json
{ "errors": { "title": ["can't be blank"] } }
```

## 9. 技術選定

| 層 | 採用技術 | 選定理由 |
|---|---|---|
| バックエンド | Ruby on Rails 8（API モード） | 学習対象（RaiseTech）。CRUD・enum・バリデーションなどを規約に沿って高い生産性で実装でき、API 専用構成で軽量 |
| フロントエンド | Vue 3 + Vite + TypeScript（SPA） | カンバンのような動的 UI に適する。TS で型安全、Vite で高速な開発体験。学習対象 |
| データベース | MySQL 8 | 広く使われる RDB で情報が豊富。Docker でローカル環境を容易に再現できる |
| API 通信 | REST / JSON | シンプルで学習向き。今回の規模では GraphQL 等はオーバースペック |
| 開発環境 | Docker（MySQL）/ mise（Ruby 3.3）/ 固定ポート | ローカル再現性を確保。ポートは Backend 3000 / Frontend 5173 / MySQL 3306 に固定（[CLAUDE.md](../CLAUDE.md) §8） |

## 10. 実装の分割方針（今後の Issue 粒度）

1. **Backend: Book モデル + マイグレーション + enum**（DB スキーマ確定）※完了
2. **Backend: /api/books CRUD エンドポイント + シリアライズ + バリデーション**
3. **Backend: リクエストスペック（テスト）**
4. **Frontend: API クライアント + 型定義**
5. **Frontend: カンバンボード表示（一覧・カラム分け）**
6. **Frontend: 追加/編集フォーム + カラム移動でのステータス更新**

各ステップを 1 Issue = 1 PR とし、本書の該当セクションを参照する。
