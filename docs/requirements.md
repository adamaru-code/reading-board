Trello 風カンバンで書籍を「読みたい / 読書中 / 読了」の 3 カラム管理するアプリの
**概要・スコープ・非機能要件・制約・将来拡張**をまとめる。技術スタックは [CLAUDE.md](../CLAUDE.md) 参照（Rails 8 API / Vue 3 / MySQL 8）。

> 本書は全体像を把握するための**概要版**です。機能・画面・データベース・技術スタックの詳細は、
> 関心事ごとに分割した各ドキュメント（下記「関連ドキュメント」）に切り出しています。
> フィールド名・enum 値・API など「決め事」は各詳細ドキュメントの表に明示しており、レビューで調整可能。
>
> **画面イメージ・操作感の認識合わせは [`prototype/`](../prototype/)（HTML/CSS/JS 単体のモック）で行い、そこで合意した機能を本書に反映している。**
> 本番実装（Rails + Vue）はこのプロトタイプの挙動を参照実装とする。

## 1. 背景・目的・課題

### 1.1 背景

読みたい本・読んでいる本・読み終えた本が頭の中や複数のメモに散らばり、**積読の把握や読書の進捗が見えにくい**。
紙のリストや汎用メモアプリでは「状態の移り変わり」を直感的に扱えない。

### 1.2 目的

書籍を **「読みたい → 読書中 → 読了」** の 3 状態でカンバン管理し、**読書状況を一目で可視化**する。
評価・感想メモも残せるようにし、読後の振り返りに使えるようにする。

### 1.3 解決する課題

| 課題 | 本アプリでの解決 |
|---|---|
| 積読・読書中の本が把握しづらい | カンバンの 3 カラムで状態を可視化 |
| 状態変更が手間 | カード移動（ドラッグ）で状態を更新 |
| 読後の評価・感想が残らない | ★評価・感想メモを書籍ごとに記録 |
| 手入力での登録が面倒 | ISBN/バーコードから書誌情報（タイトル・著者）を自動取得して登録 |
| 蔵書が増えると探しづらい | 主ジャンル・形態・タグで整理し、ジャンル/著者/タグで絞り込み |
| いつ読んだか・どれくらいで読めたか分からない | 各状態に入った日付を記録し、読了までの所要日数を表示 |

具体的な機能一覧は [機能要件](functional-requirements.md) を参照。

## 2. スコープ

### 2.1 対象（このフェーズで作る）

- 書籍の登録・一覧・編集・削除（CRUD）
- カンバンのカラム移動によるステータス変更
- ★1〜5 の評価、感想メモの記録
- ステータスによる絞り込み表示
- **ISBN/バーコードからの登録**：書誌情報（タイトル・著者）を外部書誌 API（openBD）からバックエンド経由で取得。書籍/雑誌を判定
- **種別**：主ジャンル（単一）／形態（書籍・雑誌）／タグ（複数・自由）の付与とバッジ/チップ表示
- **タグ提案**：タイトル・著者名から候補タグを提示し、クリックで追加
- **日付の記録**：各ステータスに入った日（登録日・開始日・読了日、履歴）と、読了までの**所要日数**の算出・表示
- **並び替え**：読了カラムを 読了日 / 評価 / 登録日 / 所要日数 で昇順・降順に並び替え
- **絞り込み**：ジャンル・著者名（部分一致）・タグでの一覧絞り込み（併用可）
- **カラム内の並び替え**（ドラッグ）と、カラムごとの**ページング**（20 件＋「もっと見る」）
- **ログイン・招待制の登録・パスワード変更・管理者発行の再設定リンク・アカウント削除**（[複数ユーザー対応](multi-user.md)）
- **AWS へのデプロイ**（Terraform。使うときだけ起動し、DB はスナップショットで引き継ぐ。[インフラ設計](infrastructure.md)）

### 2.2 対象外（今回は作らない）

- 複数ユーザーでの共有・コラボレーション（他人の本棚を見る等。ユーザーごとの本の管理は実装済み。§3.7）
- 全文検索（タイトル/本文の全文検索。※著者・タグ・ジャンルでの絞り込みは §2.1 で対象）、読書 log/統計グラフ
- 書誌 API 連携のうち **雑誌の書誌自動取得**（openBD は書籍中心で雑誌は非対応。雑誌はコード読取のみでタイトルは手入力）
- タグ提案の **AI/NLP 化**（本フェーズは辞書ベース。将来は AI/API 化を想定）
- 定期刊行物の号管理（雑誌の号ごと管理）
- 多言語対応（日本語 UI 前提）

## 3. 非機能要件

| 区分 | 要件 |
|---|---|
| 3.1 性能 | 蔵書 〜1,000 冊での一覧表示が**体感 2 秒以内**。API 応答は通常 **500ms 以内**。1,000 冊超を見据え、一覧は API・画面ともページング済み（カラムごとに 20 件＋「もっと見る」） |
| 3.2 想定利用者・同時実行 | **招待した少人数**（個人＋知人）を想定。本はユーザーごとに分かれる。同時アクセスは数セッション程度 |
| 3.3 データ規模 | 蔵書 **〜1,000 冊**を想定 |
| 3.4 対応ブラウザ | モダンブラウザ最新版（Chrome / Edge / Safari / Firefox）。IE は非対応 |
| 3.5 対応デバイス | **PC 優先＋スマホ・タブレット対応（レスポンシブ）**。スマホでは 3 カラムを縦積みに切り替え（[画面設計](screen-design.md) 参照） |
| 3.6 可用性 | 個人利用のため SLA は設けず**ベストエフォート**。普段はローカルで動かし、AWS は**使うときだけ起動**（常時公開しない） |
| 3.7 セキュリティ | **認証（メール＋パスワード）を実装済み**：セッション Cookie 方式（署名付き httpOnly、bcrypt）。全 `/api/books*` は認証必須で所有者にスコープ、未認証は 401。公開サインアップは無く、初期ユーザー（管理者）は seed 作成、他は管理者が発行する**招待コード**（1 回限り・7 日）で登録。ログイン中はパスワード変更可（8 文字以上・現在のパスワード確認・変更時に他端末のセッションを失効）。アカウント削除可（現在のパスワード確認・本も含め全削除・最後の管理者は不可）。パスワードを忘れた場合は**管理者が再設定リンクを発行**（24 時間有効・1 回限り、トークンは署名付きで DB 非保存）。フロントは Vite プロキシで同一オリジンのため CORS は不要（本番で別オリジンにする場合は許可オリジン限定）。本番は HTTPS 前提。ログイン・登録・パスワード変更は IP ごとに**回数制限**（超過は 429）。入力値は**サーバー側でも検証**する |
| 3.8 保守性・品質 | モデル/API をテスト（minitest）で担保。開発は Issue → Branch → PR フロー（[CLAUDE.md](../CLAUDE.md) §1）。フロントは TypeScript の型と vitest（API クライアント・ロジック・コンポーネント）で品質を確保。lint：backend は RuboCop（rubocop-rails-omakase）・Brakeman・bundler-audit、frontend は ESLint＋Prettier。CI（GitHub Actions）で backend のテスト・lint・セキュリティ検査、frontend の lint・テスト・ビルド、Terraform の fmt / validate を PR ごとに自動実行 |
| 3.9 国際化・A11y | 日本語 UI 前提（多言語は対象外）。アクセシビリティは最低限（キーボード操作・十分なコントラスト）を意識し、厳密な WCAG 準拠は対象外 |
| 3.10 ポート | ローカルは Backend 3000 / Frontend 5173 / MySQL 3306 を厳守（[CLAUDE.md](../CLAUDE.md) §8） |

## 4. 制約事項・将来拡張候補

### 4.1 制約事項

- **招待制・少人数前提**。公開サインアップは無い（§3.7）。普段はローカル、AWS は使うときだけ起動。
- 固定ポート運用（Backend 3000 / Frontend 5173 / MySQL 3306）。開発はフロントの Vite プロキシで同一オリジンのため CORS 設定は不要（[CLAUDE.md](../CLAUDE.md) §8）。
- 日本語 UI 前提（多言語は対象外）。

### 4.2 将来拡張候補（本フェーズ未実装）

- 共有・コラボレーション（他人の本棚を見る等）。※招待制の複数ユーザーは実装済み（[複数ユーザー対応](multi-user.md)）。
- 独自ドメインでの公開・常時公開（現状は `*.cloudfront.net` で使うときだけ起動。[インフラ設計](infrastructure.md)）。
- メールでの自動パスワードリセット・登録時のメール確認（SES 等。現状は管理者発行の再設定リンク）、誰でも登録できる公開サインアップ。
- **書影（表紙画像）**の取得・表示（openBD の書影 URL の利用）。
- 全文検索（タイトル/本文）、読書統計・グラフ。
- **タグ提案の AI/NLP 化**（現状は辞書ベース。タイトル・著者を AI/API に渡して候補を得る形へ差し替え）。
- 雑誌の書誌自動取得・号管理（別データ源との連携）。
- ISBN 書誌取得結果の**キャッシュ**（現状は照会のたびにバックエンドから openBD を呼ぶ）。
- 標準的な構成への改善（GitHub Issue で管理）：vue-router の導入（#158）、大きい画面部品の分割と共通モーダル（#159）、メッセージの I18n 化（#160）、本番の `config.hosts`（#161）。

## 5. 実装の分割方針（今後の Issue 粒度）

1〜10 はすべて完了。その後、seed・CI・カラム内並び替え・ページング・認証・招待制・パスワード関連・AWS（Terraform）・lint を追加した（経緯は GitHub の PR を参照）。

1. **Backend: Book モデル + マイグレーション + enum**（DB スキーマ確定）
2. **Backend: /api/books CRUD エンドポイント + シリアライズ + バリデーション**
3. **Backend: リクエストスペック（テスト）**
4. **Frontend: API クライアント + 型定義**
5. **Frontend: カンバンボード表示（一覧・カラム分け）**
6. **Frontend: 追加/編集フォーム + カラム移動でのステータス更新**
7. **Backend/Frontend: 種別（主ジャンル・形態・タグ）** — モデル拡張、バッジ/チップ表示、入力フォーム
8. **Backend/Frontend: 絞り込み**（ジャンル / 著者 / タグ、併用可）
9. **Backend/Frontend: 状態日付の記録と所要日数** — 状態イベント記録、カード表示、読了カラムの並び替え
10. **Frontend: ISBN/バーコード登録**（openBD 照会・書籍/雑誌判定・タグ提案）

各ステップを 1 Issue = 1 PR とし、該当する詳細ドキュメント（[機能要件](functional-requirements.md) / [画面設計](screen-design.md) / [データベース設計](database-design.md)）を参照する。挙動の参照は [`prototype/`](../prototype/)。
