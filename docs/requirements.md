## 1. 背景・目的・課題

### 1.1 背景

読みたい本・読んでいる本・読み終えた本が頭の中や複数のメモに散らばり、**積読の把握や読書の進捗が見えにくい**。
紙のリストや汎用メモアプリでは「状態の移り変わり」を直感的に扱えない。

### 1.2 目的

書籍を **「読みたい → 読書中 → 読了」** の 3 状態でカンバン管理し、**読書状況を一目で可視化**する。
評価・感想メモも残せるようにし、読後の振り返りに使えるようにする。

### 1.3 解決する課題

| 課題 | 本アプリでの解決 |
|---|---|
| 積読・読書中の本が把握しづらい | カンバンの 3 カラムで状態を可視化 |
| 状態変更が手間 | カード移動（ドラッグ）で状態を更新 |
| 読後の評価・感想が残らない | ★評価・感想メモを書籍ごとに記録 |

具体的な機能一覧は [機能要件](functional-requirements.md) を参照。

## 2. スコープ

### 2.1 対象（このフェーズで作る）

- 書籍の登録・一覧・編集・削除（CRUD）
- カンバンのカラム移動によるステータス変更
- ★1〜5 の評価、感想メモの記録
- ステータスによる絞り込み表示

### 2.2 対象外（今回は作らない）

- ユーザー認証・アカウント管理（→ §4 将来拡張候補で想定を明記）
- 複数ユーザーでの共有・コラボレーション
- 全文検索、タグ・カテゴリ、読書 log/統計グラフ
- 外部サービス連携（書影 API・書誌情報の自動取得など）
- 多言語対応（日本語 UI 前提）

## 3. 非機能要件

| 区分 | 要件 |
|---|---|
| 3.1 性能 | 蔵書 〜1,000 冊での一覧表示が**体感 2 秒以内**。API 応答は通常 **500ms 以内**。1,000 冊超を見据え、将来ページング（1 回 50〜100 件）を導入できる設計余地を残す |
| 3.2 想定利用者・同時実行 | **単一ユーザー**を前提。同時アクセスは基本 1、ピークでも数セッション程度 |
| 3.3 データ規模 | 蔵書 **〜1,000 冊**を想定 |
| 3.4 対応ブラウザ | モダンブラウザ最新版（Chrome / Edge / Safari / Firefox）。IE は非対応 |
| 3.5 対応デバイス | **PC 優先＋スマホ・タブレット対応（レスポンシブ）**。スマホでは 3 カラムを縦積みに切り替え（[画面設計](screen-design.md) 参照） |
| 3.6 可用性 | 個人利用のため SLA は設けず**ベストエフォート**。ローカル / 自己ホスト前提 |
| 3.7 セキュリティ | 認証は本フェーズ対象外だが、**将来的に単一ユーザー認証（メール＋パスワード等）を追加する前提**でモデル/API を拡張しやすく保つ（→ §4 将来拡張候補）。CORS は許可オリジンを `http://localhost:5173` に限定（[CLAUDE.md](../CLAUDE.md) §8）。本番は HTTPS 前提。入力値は**サーバー側でも検証**する |
| 3.8 保守性・品質 | モデル/API をテスト（minitest）で担保。開発は Issue → Branch → PR フロー（[CLAUDE.md](../CLAUDE.md) §1）。フロントは TypeScript の型と Lint で品質を確保 |
| 3.9 国際化・A11y | 日本語 UI 前提（多言語は対象外）。アクセシビリティは最低限（キーボード操作・十分なコントラスト）を意識し、厳密な WCAG 準拠は対象外 |
| 3.10 ポート | ローカルは Backend 3000 / Frontend 5173 / MySQL 3306 を厳守（[CLAUDE.md](../CLAUDE.md) §8） |

## 4. 制約事項・将来拡張候補

### 4.1 制約事項

- **単一ユーザー・ローカル / 自己ホスト前提**。認証は本フェーズ対象外（§2.2）。
- 固定ポート運用（Backend 3000 / Frontend 5173 / MySQL 3306）。CORS は `http://localhost:5173` のみ許可（[CLAUDE.md](../CLAUDE.md) §8）。
- 日本語 UI 前提（多言語は対象外）。

### 4.2 将来拡張候補（本フェーズ未実装）

- **単一ユーザー認証**（メール＋パスワード等）。導入時は `users` テーブルを追加し、`books` に `user_id` を持たせて 1 対多で紐づける想定（ER 図は [基本設計（図）](basic-design.md) §3.1）。
- 蔵書 1,000 冊超に備えた一覧ページング。
- タグ・カテゴリ、全文検索、読書統計。

## 5. 実装の分割方針（今後の Issue 粒度）

1. **Backend: Book モデル + マイグレーション + enum**（DB スキーマ確定）※完了
2. **Backend: /api/books CRUD エンドポイント + シリアライズ + バリデーション**
3. **Backend: リクエストスペック（テスト）**
4. **Frontend: API クライアント + 型定義**
5. **Frontend: カンバンボード表示（一覧・カラム分け）**
6. **Frontend: 追加/編集フォーム + カラム移動でのステータス更新**

各ステップを 1 Issue = 1 PR とし、該当する詳細ドキュメント（[機能要件](functional-requirements.md) / [画面設計](screen-design.md) / [データベース設計](database-design.md)）を参照する。
